## Technical Implications

**No Architecture Impact — Pure Frontend:**
- Backend Application API already implemented (5 endpoints with RBAC)
- Shared types already exported (Application, CreateApplicationInput)
- All changes follow existing organizational patterns (organizations/page.tsx model)
- applicationId is optional FK (enforced at controller layer, not DB constraints)

**Data Flow:**
- Users create Application first → then Device/Workflow linked to that Application
- No cascade deletes (delete guard on Application prevents orphaning)
- Slug auto-generated by backend on POST/PATCH (frontend shows read-only preview)
- isActive toggle inline in table (SuperAdmin only)

**Constraints:**
- Applications list shows 0 device/workflow counts (placeholder stats) — backend doesn't return counts in list endpoint
- applicationId in forms is optional (nullable) — users can create devices/workflows without scoping to app
- No Redux needed (local useState pattern like organizations page)
